# Webcam Go 5.0 — OBS preview 4

На ветке OBS используйте `START_OBS.bat` для передачи принятых камеры, экрана и звука прямо в OBS. [Инструкция](https://github.com/bukirev/webcam-low-latency/blob/obs-teleport/go-version/OBS.md).

Разработчикам: [модули и архитектура](https://github.com/bukirev/webcam-low-latency/blob/main/docs/README.md),
[инструкции для агентов](https://github.com/bukirev/webcam-low-latency/blob/main/AGENTS.md),
[опыт и перенос](https://github.com/bukirev/webcam-low-latency/blob/main/docs/porting-guide.md).

Исправлен вылет сервера через несколько минут при передаче экрана: перечисление
мониторов и окон теперь использует постоянные callbacks Windows и освобождает
контекст каждого вызова. Проверка выполняет 8 000 перечислений мониторов и 2 000
перечислений окон, включая параллельные вызовы.

Отдельная нативная версия для **Windows 10/11 x64**: веб-камера, экран,
системный звук и микрофон по локальной сети. Один `WebcamGo.exe`, без Python,
OpenCV, FFmpeg, установки Go и папки `_internal`.

Распакуйте эту предварительную Go-сборку в отдельную папку.

## Запуск

1. На передающем компьютере запустите `START_SERVER.bat`, на принимающем —
   `START_CLIENT.bat`. Прямой запуск EXE открывает приёмник; режим меняется в панели.
   `START_LOCAL.bat` включает локальный просмотр без передачи в сеть.
2. На приёмнике задайте IP передатчика. Пустое поле включает поиск в локальной сети.
3. Настройки камеры, экрана и звука находятся в трёх вкладках одной панели.
   Нажмите **«Применить»**, затем **«Запустить выбранное»**.
4. Камера и экран открываются в отдельных окнах. Каждый поток запускается и
   останавливается отдельно. Закрытие окна останавливает его поток; закрытие панели
   останавливает всё приложение.

В режиме приёмника скрыты настройки захвата и передатчика. Кнопка применения одна
для всех вкладок. Изменения в полях и выбор пресета не влияют на работающие потоки
до нажатия **«Применить»**. Формат и устройство меняются с перезапуском потока;
обработка изображения и громкость меняются во время работы.

В окне просмотра: **F11** — полный экран, **Esc** — выйти из него, **F5** — снимок.
Снимки с текущей обработкой, масштабом и поворотом сохраняются в `snapshots` рядом
с EXE. Все параметры вида действуют на локальное окно; изображение для других
приёмников они не изменяют.

## Камера, экран и звук

- Камера захватывается через Windows Media Foundation. В режиме **MJPG** JPEG
  камеры передаётся без декодирования и повторного сжатия. Качество такого JPEG
  задаёт драйвер камеры, поэтому соответствующее поле скрыто. Для другого режима
  используется преобразование Windows и JPEG-кодирование WIC. Доступный режим,
  ближайший к заданным разрешению и FPS, показывается в статусе.
- Экран: монитор, все мониторы, область с выбором мышью на снимке монитора либо
  координатами, видимая область выбранного окна. Можно задать FPS, ширину, качество,
  курсор и паузу. Свёрнутое или перекрытое окно не захватывается как скрытая поверхность.
- WASAPI передаёт **системный звук и микрофон вместе** по умолчанию. Источники,
  уровни каждого источника, частота, число каналов, блок, отключение отправки,
  динамики, громкость, буфер и отключение воспроизведения настраиваются в панели.
  Локальный режим захватывает звук без воспроизведения во избежание обратной связи.
- При отключении источника приложение повторяет подключение. Ошибки устройств
  и занятых портов показываются в панели.

## Нагрузка и задержка

Вывод, масштабирование, яркость, контраст, насыщенность, гамма и резкость выполняются
через **Direct3D 9 / pixel shader 3.0**. Нужны работающий видеодрайвер и системная
`d3dcompiler_47.dll` из Windows. JPEG декодирует WIC на CPU; переход на Go сам по себе
не устраняет эту нагрузку.

Очередь видео хранит только свежий кадр. При свёрнутом окне и отключённом
предпросмотре декодирование приостанавливается. **«Экономия CPU обоим» → «Применить»**
выбирает 20 FPS и JPEG /2 у обоих локальных просмотров; звук не замедляется.
Для исходного качества выберите JPEG /1 и FPS 0. Реальный CPU и задержка зависят
от компьютера, разрешения, драйвера и сети. На Intel 5405U пользователь сообщил
о снижении суммарного CPU с более 30% до менее 9% при прежней задержке и лучшем
субъективном качестве экрана. Это наблюдение одной установки, а не лабораторное
измерение или гарантия для другого компьютера.
[Контекст результата](https://github.com/bukirev/webcam-low-latency/blob/main/docs/lessons-learned.md).

## Совместимость и настройки

Форматы UDP сохранены: камера `WC30`, порт 5001; экран `WS40`, порт 5002;
PCM16 звук `WA40`, порт 5003. Можно подключать Go-приёмник к передатчику 4.3 и наоборот.
Экранный и звуковой порты можно изменить, их значения должны совпадать на обеих сторонах.
Приложение предназначено для доверенной локальной сети; шифрование и авторизация
медиапотоков протоколом не предусмотрены. Разрешите приложению доступ в частной сети
в брандмауэре Windows и доступ к камере/микрофону в параметрах Windows.

Профили Go сохраняются рядом с EXE: `settings_go_client.json`,
`settings_go_server.json`, `settings_go_local.json`. Если профиля Go нет, импортируются
лежащие рядом `settings_<режим>.json` и `settings_screen_<режим>.json` прежней версии.
Python-профили не перезаписываются. Для переноса скопируйте нужные профили рядом с EXE.

Диагностика сохраняется в `logs/session-<дата>-<номер процесса>.log`: версия,
запуск/остановка потоков, состояние памяти и аварийный стек при сбое. Изображения
и записи звука туда не попадают. Сохраняются последние 20 сеансов; если папка EXE
недоступна для записи, используется `%LOCALAPPDATA%/WebcamGo/logs`.
Для запуска сервера сразу с обоими потоками: `WebcamGo.exe server --autostart`.

Ограничение первой сборки: ручные аппаратные экспозиция, фокус и баланс белого
из Python-интерфейса не перенесены в панель — их доступность через Media Foundation
зависит от драйвера. Используйте настройки драйвера камеры или стабильную версию 4.3,
если нужны именно эти регулировки. GPU-вывод и звук следует проверить на целевом ПК.

## Сборка из исходников

Установите Go 1.27.4 или новее под Windows x64 и выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\go-version\build.ps1
```

Скрипт запускает тесты, добавляет manifest через закреплённую версию `rsrc`, собирает
EXE с `CGO_ENABLED=0`, добавляет лицензии зависимостей и создаёт
`release/WebcamGo-OBS-Windows-x64.zip`. C/C++-компилятор не нужен.
Проверка Windows API: `WebcamGo.exe --self-test`, результат — `go-self-test.json`
рядом с EXE. Она кратковременно включает камеру, захват экрана и микрофон, проверяет
WIC, Direct3D и WASAPI; изображения и записи звука на диск не сохраняет.
