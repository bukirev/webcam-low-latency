# session.go — повторный запуск worker

[Исходник](../../go-version/session.go)

`retryMedia(ctx, run)` выполняет run до его возврата, затем ждёт секунду либо cancel.
Если context уже отменён, новый запуск не начинается. Текущий run обязан сам
проверять context или прерывать своё ожидание и освободить ресурсы до возврата.

Это минимальный уровень восстановления после отключённого устройства, занятого
порта или временной ошибки API. Он используется для camera/screen source, sender,
WASAPI capture/playback и audio network worker в соответствующих местах панели.
Video receiver имеет похожий внешний цикл внутри protocol.go.

Контракт специально узкий:

- Retry не ловит panic и fatal runtime; callback exhaustion им не исправляется.
- Таймер не прерывает заблокированный DLL/COM-вызов. Нет отдельного heartbeat watchdog.
- Задержка постоянная, без exponential backoff, jitter и максимального числа попыток.
- Нет error return/run result type: сообщение об ошибке выставляет сам worker в Status.
- Нет join старого Session при смене конфигурации; cancel и retry — разные механизмы.

При переносе в сервис стоит определить typed outcome (retryable/permanent/cancelled),
лимиты попыток, jitter и наблюдаемость. Если необходимо пережить аварии native драйвера,
изолируйте его в дочернем процессе: recover в горутине не заменяет процессную границу.
При тестировании нужны инициализационная ошибка, cancel во время delay и зависший
источник; отдельного набора tests для retry в текущем репозитории нет.
