## Модель

`Config{Role,Host,Camera,Screen}` — один опубликованный снимок. Screen содержит
как экран, так и звук. `Values map[string]any` сохраняет исторический JSON:
FPS, размеры, порты и часть списков представлены строками, часть регуляторов числами.
Bool принимает именно bool. Num понимает int/float64/string и при ошибке даёт 0;
Str неизвестного ключа даёт `"<nil>"`. Эти helpers не заменяют валидацию.

Schema встраивается в EXE через `//go:embed`; рядом с EXE JSON не нужен.
`defaults` задаёт исходные значения; camera/screen/audio — записи
`[group,key,label,options]`; client — списки допустимых полей приёмника.
Два числовых options означают диапазон, строки — список, `devices` — динамический
источник GUI, null вместе с bool default означает checkbox.

## Загрузка и сохранение

1. `defaultConfig` копирует defaults.
2. Старые `settings_<role>.json` и `settings_screen_<role>.json` накладываются
   только по известным ключам.
3. Если есть Go-профиль `settings_go_<role>.json`, он накладывается поверх Config.
4. Роль соответствует выбранному профилю. Если `Host` отсутствует в Go-профиле,
   берётся импортированный адрес. Сохранённая пустая строка восстанавливает
   автоматический поиск.

Python-файлы не перезаписываются. Фактическая последовательность накладывания важна:
старые параметры читаются и при наличии Go-профиля, а Go-значения имеют приоритет.
Если Go-профиль не разбирается целиком, сохраняются defaults и импортированные значения.

`settings_go_panel.json` рядом с EXE хранит последний режим, вкладку,
раскрытие дополнительных разделов и выбор окон предпросмотра передатчика.
Явно заданная роль запуска имеет приоритет. Валидные параметры формы сохраняются
при применении, выходе и смене роли. При выходе и смене роли этот снимок не публикуется
в работающие потоки. Обычный запуск восстанавливает форму с остановленными потоками.

Save сериализует Config в temp рядом с профилем и делает Rename. Ошибка возвращается
панели. Это защита от частичной записи при обычной работе, но нет явного fsync,
backup, schema-version migration и универсальной гарантии атомарной замены Windows.

## Публикация между горутинами

`ConfigStore.Set` клонирует Camera/Screen и кладёт Config в atomic.Value.
`Get` возвращает содержащиеся maps без новой копии: **потребители их не меняют**.
Для draft используется Clone, затем новый Set. Atomic защищает публикацию снимка,
а не конкурентное редактирование map после Get.

Clone поверхностный. В текущей схеме значения скалярные; добавление slice/map
потребует глубокого копирования или типизированной неизменяемой модели.
При выделении библиотеки желательно заменить Values на typed configuration
и вынести файловое хранилище и смену cwd из алгоритмического пакета.

## Валидация и ограничения

Проверяются роль, host без пробелов/контролов, диапазоны и enum, конфликт портов.
На client source fields пропускаются: бесполезное значение source FPS не должно
мешать приёму. Наличие камеры, окна, endpoint и работоспособность native format
определяются соответствующим worker во время запуска.

Скрытая hardware camera group на server всё ещё входит в общую валидацию source
профиля. Скрытие поля в UI не равно исключению из validator; повреждённое старое
значение иногда придётся исправить в профиле либо отдельной миграцией.

Это не полный JSON schema validator: строгая проверка типов bool, всех пустых
значений и всех сочетаний параметров реализована не везде. Для чисел за диапазоном
validate вернёт ошибку, но часть числовых преобразований допускает усечение Int.
Не используйте `Values.Num` напрямую как валидатор внешнего недоверенного JSON.

Дублирующиеся ключи требуют kind: camera.top — bool «поверх окон», screen.top —
числовая Y-координата; screen.topmost — флаг верхнего окна. Поля нельзя объединять
одной глобальной картой по одному key без namespace.

Проверки включают [settings_test.go](../../go-version/settings_test.go),
`TestClientIgnoresUnusedSenderSettings` и self-test `validate(panel.draft())`
для client/server/local.
