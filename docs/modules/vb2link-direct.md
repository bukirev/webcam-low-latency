# Прямые источники VB2Link для OBS

Исходники входят в [obs-plugin](../../obs-plugin/README.md). [module.c](../../obs-plugin/module.c)
работает с API libobs, [bridge.h](../../obs-plugin/bridge.h) задаёт границу ABI,
[plugin.go](../../obs-plugin/plugin.go) управляет приёмом и рабочими горутинами.
Публичный [скрипт сборки](../../obs-plugin/build.ps1) перечисляет точные Go-файлы,
копируемые в C-shared пакет. Их лицензионный охват определён в [LICENSING.md](../../obs-plugin/LICENSING.md).

| Имя в OBS | Постоянный ID | Вход | Выход |
|---|---|---|---|
| VB2Link Camera | `webcamgo_camera` | WC30, 5001 | WIC → BGRA → асинхронное видео libobs |
| VB2Link Screen | `webcamgo_screen` | WS40, 5002 | WIC → BGRA → асинхронное видео libobs |
| VB2Link Audio | `webcamgo_audio` | WA40, 5003 | PCM16 → float32 → микшер OBS |

## Настройки и сеть

OBS хранит адрес, порт и, для видео, лимит FPS и делитель декодирования 1, 2 или
4 в настройках каждого источника. Кнопка поиска наполняет выпадающий список
откликами нужного типа потока. Можно сочетать камеру одного ПК, экран второго
и микс звука третьего. Несколько OBS или обычных приёмников могут одновременно
подписываться на один передатчик. Сетевой расход растёт с числом подписок,
адаптация видео использует общую ступень для подписчиков этого потока.

Приём по указанному IP, поиск, подписка, ограничение времени жизни и сообщения
STAT описаны в [контракте UDP](../protocols.md). Для старого отправителя можно
ввести IP вручную. Облегчение декодирования в OBS действует локально. STAT
сообщает о собранных JPEG до WIC, поэтому отбрасывание кадров декодером в OBS
не выглядит для передатчика как сетевые потери.

## Жизненный цикл и память

При создании и изменении настроек C-объект запускает Go worker с парой горутин.
Одна читает UDP, вторая публикует данные в libobs. C хранит целое
`cgo.Handle`. При остановке `webcam_stop` отменяет context, ждёт обе горутины,
затем удаляет handle. Это сохраняет валидность указателя на источник OBS до
последнего вызова из Go. Обновление настроек останавливает предыдущий worker
до создания нового.

Видео хранит один свежий JPEG в Latest. Worker создаёт WIC на закреплённом
COM-потоке, проверяет видимость источника и ограничение частоты до декодирования.
При отсутствии маркера EOI пробует добавить его в копию буфера. WIC всё равно
может отклонить повреждённый JPEG. Видеобуфер освобождается после синхронного
вызова libobs, который копирует кадр. При тайм-ауте источника пустой кадр очищает
вывод.

Аудио проходит через ограниченный канал из восьми пакетов. Плагин получает
смешанный сигнал передатчика и передаёт float32-сэмплы в OBS с временными
метками по счётчику сэмплов и монотонным часам OBS. У видео и звука нет общей
метки времени захвата, поэтому синхронизация разных устройств зависит от цепочек
источников и настроек сцены.

## Проверка после изменений

Сверьте регистрацию трёх ID, запуск из сохранённой сцены, смену адреса и порта,
поиск двух отправителей, освобождение ресурсов при удалении источника,
возврат картинки при повторной подписке и поступление звука в микшер. Результаты
с версиями OBS фиксируйте в [журнале проверок](../verification-log.md).
Для отдельного пути UDP → Teleport действует [собственная инструкция](obs.md).
