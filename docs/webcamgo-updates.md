# Единая установка и обновления VB2Link

[Скачать единый установщик Windows x64](https://github.com/bukirev/webcam-low-latency/releases/download/suite-v0.1.0-preview.5/VB2Link-Setup-Windows-x64.exe) · [Версии и SHA-256](release-log.md) · [Журнал проверок](verification-log.md)

`VB2Link-Setup-Windows-x64.exe` устанавливает передатчик и плагин OBS из одного
окна. Можно отметить один или оба компонента. Первая установка работает с
пакетами внутри EXE без сети. В VB2Link нажми **О проекте → Открыть обновлятор**.
Из меню «Пуск» менеджер также доступен через **VB2Link — установка и обновления**.
Если менеджер ещё не зарегистрирован, VB2Link предложит открыть страницу
выпусков. Запусти скачанный установщик и нажми **Создать ярлык**, если нужные
компоненты уже установлены.

Перед заменой закрой выбранную копию передатчика или OBS. Установка меняет
только `WebcamGo.exe` и/или `webcamgo-direct.dll` в выбранных папках и хранит по
одной резервной копии. Профили, коллекции сцен и другие плагины сохраняются.
На ПК с передатчиком без OBS запись в папку OBS не требуется.

## Установка по ролям и переход со старого канала

1. На ПК захвата выбери передатчик. На ПК монтажа выбери плагин OBS и укажи
   корневую папку рабочей OBS. Если оба компонента нужны на одном ПК, выбери оба.
2. После установки открой VB2Link на передатчике, выбери камеру, экран и входы
   звука, примени настройки и запусти нужные потоки. В OBS добавь
   [прямые источники](modules/vb2link-direct.md) и закрепи отправителя по IP.
3. Если на компьютере есть отдельный менеджер передатчика или плагина, запусти
   новый единый EXE один раз, укажи существующие папки и нажми **Создать ярлык**
   при уже действующих версиях либо установи нужные обновления. У отдельных
   менеджеров свои каналы. Единый менеджер после этого открывается из меню «Пуск».

Сами компоненты имеют независимые версии. Для смены версии менеджера скачай и
запусти его новый EXE. Удалённая сторона обновляется на своём компьютере.

## Что означает совместимость

Версия выпуска менеджера и версии двух компонентов независимы.
[Таблица контрактов](../obs-plugin/setup/compatibility-policy.json) связывает
каждую версию компонента с поддерживаемыми протоколами и функциями:

- `udp-jpeg-pcm-v1` — камера, экран и звук по текущему UDP-протоколу.
- `discovery-v1` — поиск передатчика по имени.
- `multi-camera-discovery-v1` — поиск нескольких камер одного ПК и выбор каждой по имени, IP и порту.
- `video-feedback-v1` — обратная связь, на которой основана адаптация по потерям.

Для передачи нужен хотя бы один общий протокол. Дополнительные возможности
появляются, когда их поддерживают обе стороны. Например, передатчик
`0.1.0-preview.1` и плагин `0.1.0-preview.2` имеют общий базовый протокол.
Адаптация по потерям требует поддержки `video-feedback-v1` с двух сторон,
начиная с передатчика `0.1.0-preview.2` и плагина `0.1.0-preview.3`.

Менеджер читает версии исполняемых файлов на текущем ПК. Версию удалённой
стороны вводит оператор. При неизвестной версии менеджер допускает обновление
с сохранением текущих протоколов, а при смене протокола требует указать вторую
сторону. Если обновляются оба локальных компонента, он проверяет промежуточную
пару. При переходе, который ломает обе последовательности, нужен промежуточный
выпуск с поддержкой старого и нового протоколов. Этот же принцип применяется
перед откатом. Перед записью проверяются все запрошенные пакеты.

## Локальное состояние и откат

| Файл | Назначение |
|---|---|
| `%LOCALAPPDATA%\WebcamGo\VB2Link-Setup.exe` | Копия единого менеджера, которую открывает ярлык в «Пуске» |
| `%LOCALAPPDATA%\WebcamGo\manager.json` | Выбранные папки и данные менеджера |
| `%LOCALAPPDATA%\WebcamGo\compatibility.json` | Последний проверенный сетевой каталог |
| `WebcamGo.exe.backup` или `webcamgo-direct.dll.backup` рядом с активным файлом | Предыдущая версия отдельного компонента |

Перед записью менеджер проверяет версии и контракты всех выбранных пакетов,
закрытие нужного приложения и возможность записи. При необходимости Windows
показывает запрос прав на защищённую папку. Файл готовится в каталоге цели,
затем заменяется средствами Windows. При недоступной DLL сохраняется активная
копия. **Восстановить предыдущую** применяет предыдущую версию с той же
проверкой совместимости. При обновлении двух компонентов менеджер выполняет
две последовательные операции. Если вторая завершится ошибкой, первая может
уже стоять в новой версии. Сверь установленные версии и повтори операцию для
оставшегося компонента либо используй разрешённый менеджером откат.

## Подготовка выпуска

1. Зафиксируй отдельные версии передатчика и плагина. Добавь их контракты в
   `compatibility-policy.json`. Сохраняй записи уже опубликованных версий.
2. Запусти [build-system.ps1](../go-version/build-system.ps1) с новым `-Version`
   и явными `-SenderVersion` и `-ObsVersion`. Компоненту с пересобранными
   байтами назначь новый номер. `-UseExisting` упаковывает
   уже собранные артефакты без их пересборки. Сборке нужны локальные исходники
   менеджера и стандартные инструменты Go и OBS.
3. Скрипт проверяет матрицу совместимости, сверяет встроенные пакеты и выдаёт
   установщик, каталог `WebcamGo-Compatibility.json`, два ZIP обновления и
   лицензии в `release/suite/v<версия>/`.
4. Для доставки через онлайн-обновлятор размести эти файлы одним релизом
   `suite-v<версия>` в GitHub Releases. Статус предварительного релиза должен
   совпадать с суффиксом `-preview.N`. Сохраняй опубликованные пакеты и контракты
   неизменными.

Переименование в VB2Link меняет интерфейс, иконки и названия установщиков.
Имя устанавливаемого EXE, внутренние идентификаторы источников OBS и имена
пакетов в канале обновлений служат для совместимости с ранее выпущенными
версиями. Действующие сцены и профили используют прежние идентификаторы.

Менеджер получает опубликованный каталог и оба хеша из API GitHub. Он
проверяет размер и SHA-256 скачанных файлов, сверяет версии, идентификаторы
компонентов и SHA-256 полезной нагрузки внутри ZIP. Если онлайн-каталог
меняет уже известный контракт или байты того же пакета, он отклоняется.
При смене формата каталога выпускается новый EXE менеджера.

Каталог формата 1 содержит `release` и `components`. Для каждого компонента
`package` задаёт `version`, `size` и `sha256`, а `versions` сопоставляет номера
версий с массивами `protocols` и `features`. Каждый ZIP содержит
`package-info.json` и один исполняемый файл. Цепочка проверки опирается на HTTPS
и метаданные GitHub. Authenticode для текущего установщика не используется.

## Ресурсы Windows

[internal/brand](../go-version/internal/brand/brand_windows.go) задаёт единую
палитру, заголовок и оформление элементов Walk. [make-icons.ps1](../branding/make-icons.ps1)
собирает знак и Windows ICO с размерами от 16 до 256 пикселей. Сборка встраивает
ресурсы в EXE.

[Приветствие VB2Link](../go-version/internal/brand/welcome_windows.go) при обычном
запуске выбирает одну из трёх встроенных иллюстраций проекта. Оно показывает
подготовку приложения, а после отрисовки панели — готовность и версию. Панель
доступна после **«Спасибо, продолжить»**, Enter или Esc. Кнопка поддержки по
желанию открывает сайт автора в системном браузере. При `--autostart` и во время
аппаратной диагностики это окно пропускается. Установщик использует краткую
заставку с автоматическим переходом.
