## Скачать и запустить

### Готовая версия без Python (Windows 10/11, 64 бит)

1. Скачайте [WebcamLowLatency-Windows-x64.zip](https://github.com/bukirev/webcam-low-latency/releases/latest/download/WebcamLowLatency-Windows-x64.zip).
2. Полностью распакуйте архив в отдельную папку. Сохраните папку `_internal` рядом с `WebcamLowLatency.exe`.
3. Запустите `START_CLIENT.bat` на принимающем компьютере, `START_SERVER.bat` на передающем или `START_LOCAL.bat` для локального просмотра.

Python и установка зависимостей не требуются. Прямой запуск `WebcamLowLatency.exe` или `START.bat` открывает единую панель.

Распаковывайте новую версию в отдельную папку целиком; не смешивайте `_internal` от разных версий.

## Единая панель управления

В версии 4.2 режим, IP, запуск и все настройки камеры, экрана и звука собраны в одном окне. Панель не обрабатывает видеокадры: два окна просмотра по-прежнему работают в независимых процессах с оптимизациями CPU из версии 4.1.

1. Выберите **«Передатчик»**, **«Приёмник»** или **«Локальный просмотр»**. В режиме приёмника задайте общий IP либо оставьте поле пустым для поиска.
2. Во вкладках **«Камера»**, **«Экран»** и **«Звук»** задайте параметры. Нажмите единую кнопку **«Применить»** вверху панели.
3. Отметьте **«Запускать вместе»** на нужных карточках и нажмите **«Запустить выбранное»**. Каждый поток можно запустить или остановить отдельно.
4. Карточки показывают состояние и статистику. Кнопки открывают просмотр, полный экран и снимок. Настройки остаются в единой панели.

В режиме **«Приёмник»** показываются только действующие на нём настройки: подключение и порты, включение приёма экрана и звука, лимит FPS, масштаб декодирования, отображение изображения, динамики, громкость и буфер воспроизведения. Выбор камеры, разрешение/FPS захвата, качество отправляемого JPEG, монитор, область, системный вход, микрофон и формат записи скрыты. При смене режима на передатчик эти настройки снова доступны; сохранённые значения не удаляются.

Кнопка **«Применить»** одна для всех вкладок и обоих потоков. **«Экономия CPU обоим»** только выбирает значения — затем нажмите **«Применить»**. Нажатие **«Старт»** у уже работающего потока лишь открывает его просмотр и не применяет незавершённые изменения. Управляемые окна просмотра не содержат дублирующих панелей настроек или кнопок применения; F2 их не открывает.

**«Окно просмотра»** и **«Обновить устройства / окна»** могут открыть дочернее окно без запуска захвата и передачи. Так можно сначала выбрать монитор, микрофон, выход или область. **«Выбрать область мышью»** открывает выделение на снимке выбранного монитора. После выбора примените настройки.

Настройки работающих окон передаются кнопкой **«Применить»** без ручного закрытия и запуска BAT-файлов. Изменения вида, громкости и экономии CPU применяются без перезапуска потока; изменение формата или устройств звука перезапускает сеанс экрана и звука. Пресет **«Экономия CPU обоим»** выбирает 20 FPS и JPEG /2 для обоих приёмников.

При смене режима прежние окна останавливаются и загружается отдельный профиль нового режима. При закрытии панели останавливаются только процессы, которые она открыла. Уже открытые отдельными BAT-файлами окна к панели автоматически не подключаются.

Параметры совместимы с прежними `settings_*.json`; расположение панели хранится в `settings_dashboard.json`. Дополнительное управление между панелью и её окнами идёт только через защищённое случайным токеном соединение на этом компьютере. Сетевые протоколы передачи медиа остались совместимы с версиями 4.0/4.1.

Для прежнего запуска только камеры используйте `START_CAMERA_CLIENT.bat`, `START_CAMERA_SERVER.bat` или `START_CAMERA_LOCAL.bat`. Файлы `START_SCREEN_*.bat` по-прежнему открывают отдельное окно экрана и звука.

## Снижение нагрузки на клиенте

Версия 4.1 обрабатывает новый кадр один раз, повторно использует память изображений Tk и не обновляет настройки окна на каждом цикле отрисовки. На приёмнике OpenCV использует один поток обработки, чтобы два окна меньше конкурировали за CPU.

Для слабого компьютера в единой панели нажмите **«Экономия CPU обоим»**, затем **«Применить»**. При отдельном запуске окон доступен пресет **«Экономия CPU: 20 FPS, JPEG /2»**:

- В окне камеры — кнопка в панели настроек клиента.
- В отдельном окне экрана — вкладка **«Связь»**, раздел **«Нагрузка приёмника»**: выберите лимит 20 FPS и JPEG 1/N = 2.

После применения пресета приём ограничивается до 20 кадров/с, JPEG декодируется с половиной ширины и высоты. Изображение может стать менее чётким. Меняется только этот клиент; сервер и звук не меняются. Для полного качества выберите **JPEG 1/N = 1**, а для исходного FPS — **0 (без лимита)** и нажмите **«Применить»**.

Ограничение FPS отбрасывает лишние кадры перед декодированием, не создавая очередь и не добавляя ожидание таймера. В свёрнутом окне или при отключённом предпросмотре декодирование и отрисовка приостанавливаются, а сеть и звук продолжают работать. При восстановлении принимается свежий кадр.

Если нужна дополнительная экономия, уменьшите ширину экрана на передатчике до 1280 и разрешение камеры до 1280×720. Точный процент CPU зависит от размера окна, FPS, разрешения, настроек обработки и компьютера.

## Экран и звук — отдельное окно

В окне камеры нажмите **«Экран и звук»**, либо используйте отдельные файлы:

| Файл | Назначение |
| --- | --- |
| `START_SCREEN_SERVER.bat` | Компьютер, чей экран и звук нужно передавать |
| `START_SCREEN_CLIENT.bat` | Компьютер, на котором нужно смотреть и слушать |
| `START_SCREEN_LOCAL.bat` | Локальный предпросмотр и индикатор уровня звука |

На обоих компьютерах нажмите **«Старт / применить»**. Захват экрана и микрофона начинается только после нажатия этой кнопки. По умолчанию передаются системный звук и микрофон вместе. Можно включить только экран или только звук. На приёмнике при необходимости задайте IPv4 передатчика.

### Настройки экрана

- Один монитор, все мониторы, прямоугольная область с выбором мышью или окно.
- Захват окна передаёт видимую область рабочего стола: перекрывающие окна тоже видны, свёрнутое окно не захватывается.
- Настоящий указатель Windows; пауза видео; отключаемый локальный предпросмотр.
- FPS от 1 до 120, качество JPEG 30–95, ограничение ширины или исходный размер. Реальный FPS зависит от компьютера, размера экрана и сети.
- Вписать / заполнить / растянуть, зум, поворот, зеркало, яркость, контраст, насыщенность, гамма и резкость.
- Полный экран, поверх других окон, снимок текущего вида. Обработка вида локальная и не меняет отправляемый кадр.

### Настройки звука

- Запись системного выхода через WASAPI loopback и выбранного микрофона; независимая громкость обоих источников.
- Выбор динамиков или наушников на приёмнике, громкость и отключение воспроизведения.
- PCM 16 бит без сжатия, 16 / 24 / 44,1 / 48 кГц, моно или стерео. Оба источника приводятся к выбранному формату и смешиваются с ограничением пиков.
- Блок захвата / вывода 5 / 10 / 20 мс; буфер приёмника 10–200 мс. Это настройки буферов, а не обещание полной задержки от источника до динамиков.
- Индикатор уровня, статистика трафика, потерь пакетов и нехватки данных для воспроизведения.
- В единой панели все изменения передаются одной кнопкой **«Применить»**. При отдельном запуске окна громкость, отключение звука и пауза действуют сразу; изменения устройств и формата — после его кнопки **«Старт / применить»**.

Начните с 48 кГц, стерео, блока 10 мс и буфера 40 мс. При щелчках попробуйте блок 20 мс и буфер 80 мс. Стерео PCM 48 кГц требует примерно 1,54 Мбит/с без учёта заголовков. При микрофоне удобнее наушники: автоматического подавления эха нет. Выбранный системный выход должен совпадать с тем, через который Windows воспроизводит нужную программу.

Видео и звук используют независимые потоки с отбрасыванием устаревших данных. Строгой синхронизации губ со звуком нет; буфер звука можно подобрать вручную. Передача идёт без шифрования по доверенной локальной сети.

В локальном режиме звук не передаётся и не воспроизводится обратно — показывается только его уровень. Это исключает самопрослушивание через системный loopback.

Настройки окна сохраняются в `settings_screen_local.json`, `settings_screen_server.json` или `settings_screen_client.json` рядом с EXE. Для изменения настроек используйте доступную для записи папку.

## Запуск исходного кода с Python

1. Нажмите **Code → Download ZIP** и распакуйте архив.
2. Установите Python 3 с поддержкой tkinter. При установке включите **Add Python to PATH**.
3. Запустите нужный файл:
   - `START_LOCAL.bat` — единая панель локального просмотра.
   - `START_SERVER.bat` — единая панель передатчика.
   - `START_CLIENT.bat` — единая панель приёмника.

При первом запуске зависимости из `requirements.txt` устанавливаются автоматически; для установки нужен интернет. Поддерживаемая среда готовой сборки — Python 3.13 x64 на Windows.

## Передача по сети

Оба компьютера должны находиться в одной локальной сети. Клиент автоматически ищет передатчик; при необходимости укажите IPv4 компьютера с камерой вручную.

Разрешите приложение (`WebcamLowLatency.exe`, а при запуске исходников — Python) в брандмауэре Windows для частных сетей. Клиенты используют динамические UDP-порты. Порты передатчика по умолчанию:

| Поток | UDP-порт |
| --- | --- |
| Камера | 5001 |
| Экран | 5002 |
| Звук | 5003 |

Порты экрана и звука можно изменить, указав одинаковые значения на передатчике и приёмнике. Видео и звук не шифруются: используйте доверенную локальную сеть и не открывайте порты в интернет.

Рекомендуемые параметры: Ethernet, 1280×720, MJPG, 30/60 FPS и качество JPEG 75–80. Доступные режимы зависят от камеры.

## Управление

- **F2** — показать или скрыть настройки.
- **F11** — полный экран.
- **F5** — снимок в папку `snapshots`.
- **Esc** — выйти из полного экрана или закрыть приложение.

Обработка изображения применяется к локальному просмотру. Аппаратные настройки камеры задаются на передатчике. Настройки сохраняются отдельно для каждого режима.

Дополнительная информация: [README.txt](README.txt).

## Проверка и сборка

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m pip install pyinstaller==6.16.0
.\build_portable.ps1
```

Архив готовой сборки создаётся в `release/WebcamLowLatency-Windows-x64.zip`. Пользовательские настройки и снимки в него не включаются. Лицензии зависимостей находятся в папке `third-party-licenses`.

Захват экрана: [MSS](https://python-mss.readthedocs.io/stable/). WASAPI-захват и воспроизведение: [PyAudioWPatch](https://github.com/s0d3s/PyAudioWPatch).

Измерение клиентского пути обработки (исходники, Git с тегом `v4.0.0`, Windows): `python tools/benchmark_client.py`. Результат содержит процессорное время для одинаковых кадров; это не измерение процента CPU на удалённом компьютере.
